## 已发现的差异与处理

1. 实施说明的“D1 题目全被暴露”是假设。实际 SQL 21dev/9holdout、RAG14dev/6holdout；补题后采用 SQL35/15、鲁棒21/9、RAG21/9，旧保留题继续保留，不在 D2 运行。
2. 原《方案.md》中的客单价、复购客户定义不充分；以具体口径提案请求 A/B 核对，收到明确共同同意后记录。曲目热门默认数量与客户“谁买得最多”金额按查询对象区分，不统一成一个全局默认。
3. 现有 Evidence.page 已双方确认 PDF 物理页从1计，非分页格式使用现有 null＋章节路径；新增信息沿用 metadata/filters/unresolved，避免改动已同意的 schemas.py。
4. D2 不实现 D3 的完整澄清分级、交互切换、多轮状态或 AdventureWorks 链路。五级链接的真歧义只用现有 NEEDS_CLARIFICATION 输出候选。
5. 原 D1 SQL 和 OHR 题库文件属于溯源证据，保留不改。D2 SQL 使用 `eval/datasets/nl2sql_chinook_d2.jsonl`，与拟议通用文件名的对应关系在实际命令中明确；RAG 使用 `rag_single.jsonl`。
6. 按用户最新要求，尚需人工审核的别名、gold、RAG 答案与忠实度统一留到末尾审核；工程实现与草稿 gold 开发实跑继续推进。已明确共同批准的四项指标保留既有确认，不重复请求审核。正式评测入口仍保留人工接受门槛。
7. 总计划要求 OHR20＋自建文档10。准备阶段的一道扫描 OHR 自编问题不满足“自建文档”的来源范围，正式预测前换为自编指标手册题；原准备版本、纠正说明与独立 OCR 联调题保留。题量、开发/保留划分和业务口径均未改变。

## 执行顺序

基线核对 → A 值索引/链接与 B 资料/解析并行 → 记录已获批准的指标口径、隔离待审别名 → 依次构建真实值与文档向量 → 公共 API/UI 接入 → 模块与安全测试 → 仅开发集草稿实跑 → 分类修复与回归 → 日终截图、九项报告、统一审核表与附件核验。人工审核完成后再运行正式成绩入口；保留集仍等 D5 冻结。
