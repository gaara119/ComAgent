## 1 方案概述

### 1.1 任务边界与评分对应

官方要求是在不限定具体实体类型的前提下，识别别名并对非标准输入纠错、标准化改写。[S0，第5页] 本模块解决“这段话具体指谁／什么”，不替②重复训练一个抽取器，也不替③猜测缺失的时间和统计口径。

| 评分位置 | 官方口径 | 本模块可以提供的证据 |
| --- | --- | --- |
| 初赛第10页：中级任务攻克数量与质量 | 每攻克1项基础5分，整项上限15分 | 开放类型、未见别名、误改控制及完整改写链路 |
| 初赛第10页：系统鲁棒性 | 10分共同项 | 错别字、简称、中英混写下的恢复与拒绝误改 |
| 决赛第12页：智能意图理解与澄清 | 10分共同项，4／7／10分档 | 准确提供实体候选，与③联动，不等于①单独获得10分 |
| 决赛第13页：攻克广度与深度、攻克质量 | 分别15分与10分，共享评分项 | 与字典／直接LLM方案的改进、跨域证据及可解释性 |

没有独立的“别名识别准确率达到X即可满分”条款。以下指标和试验规模为项目设计；不能把关联评分全部相加成①的保证得分。

### 1.2 选定路线

| 版本 | 实现路线 | 升级条件 |
| --- | --- | --- |
| 第一版 | 复用②的描述驱动抽取器＋别名字典／字面检索／BGE-M3召回＋候选重排＋受控改写 | 用冻结测试集验证误改率和未知对象识别 |
| 第二版 | 困难负例训练重排器、校准拒识阈值、把高频消歧蒸馏到小模型 | 有经过复核的训练标注，且不能泄漏测试实体 |

**为什么选它：**把“有没有找到这段词”“候选里有没有正确对象”“最后选得对不对”“改写有没有改变原意”拆开，可定位错误，并且接入新领域时主要更新业务目录。

### 1.3 方法空间与研究依据

| 方法族 | 优点与限制 | 本项目决定 |
| --- | --- | --- |
| 精确字典、正则、编辑距离、拼音相近 | 快、可解释；未登记别名和同名对象是边界 | 用作候选召回，不能单独决定替换 |
| 固定类别NER | 边界检测稳定；固定类别与开放类型目标不一致 | 仅作基线 |
| 开放类型抽取 | 按类型描述找片段，适合复用 | 由②提供，①不重复部署 |
| 纯LLM自由重写 | 起步简单；可能把猜测变成新条件 | 基线，不进入直接执行路径 |
| 检索＋上下文重排 | 将实体描述与原文上下文共同判断 | 第一版主体 |
| 生成式实体链接、图推理 | 可表达复杂关系，但约束和数据建设更重 | 作为旁路比较，不做前置依赖 |
| 微调、蒸馏 | 可减少调用成本；需要可靠样本 | 第二版选项 |

GLiNER以类型条件识别实体，GLiNER2进一步统一结构化提取等任务；它们提供“找到原文片段”的方法，并不自动给出我们数据库中的标准ID。[R1][R2] BLINK将实体链接拆成双编码器召回和交叉编码器重排，本项目借鉴这个分工，而不是复制其数据或历史成绩。[R4] BGE-M3提供多语言检索表示，本项目仍需单独验证中文别名与英文业务名称的匹配。[R7]

当前GLiNER2官方实现区分英文和多语checkpoint，并提醒分词边界设置会影响质量；不把一个英文默认checkpoint的能力直接外推到中文。[R3] 本方案的“目录约束＋拒识＋可逆修改记录”是项目组合设计，不宣称为上述论文原算法。

## 2 设计原则

**识别、链接、改写分开。**抽取成功不等于匹配正确；匹配正确也不意味着可以补出用户没说的统计口径。

**开放类型不等于没有业务依据。**类型可以从领域描述动态载入；新类型可以提出待登记候选，但标准对象必须有可核验来源。找不到真实对象时返回未知，不能虚构ID。

**原文永远保留。**大小写、繁简、空格等规范化仅作用于检索副本，字符位置通过映射回到原文。产品编号、金额、否定、比较方向、时间和Top N默认是受保护内容。

**字面相近不等于语义相同。**“订单金额”“已收款金额”“净销售额”不能因向量相似就合并。当前数据结果碰巧相同，也不能证明业务定义等价。

**用户决定权与系统知识分开。**候选证据不足先检索；真实存在多个业务解释时交③。权限不允许看到的实体不能作为澄清选项泄漏。

## 3 技术栈

| 组件 | 选型 | 模块责任 |
| --- | --- | --- |
| 公共接口和校验 | Python、FastAPI、Pydantic | 请求结构、候选与改写对象校验 |
| 共享抽取 | ②的GLiNER2多语接口，DeepSeek按需补充 | 不重复识别同一输入 |
| 候选索引 | PostgreSQL、pgvector、字面倒排／trigram索引 | 精确、近似、语义三路检索 |
| 表示模型 | BGE-M3 | 概念描述与提及上下文编码 |
| 重排与裁决 | 第一版DeepSeek V4.1 Flash在有限候选中选择；后续小型交叉编码器 | 输出对象ID、证据和不确定状态 |
| 状态和界面 | 沿用03的LangGraph与Vue | 查看原文—标准词差异，接受③的确认结果 |
| 测试 | 固定JSONL、自动断言、人工双审 | 边界、链接、改写与端到端分开测 |

模型与工具都经过统一适配层；固定实际模型标识、checkpoint、schema和提示词版本。不把项目代号直接当成服务商API参数。[S1]

## 4 实现方案

### 4.1 数据接入：先有真实目录，再处理别名

Chinook作为第一条完整链路：从实际表中提取艺术家、专辑、曲目、流派、客户及地理值，目录保留原始主键和所属表。官方脚本是字段依据；例如`artist`、`album`、`track`有各自ID，不能仅按名称连接。[D2]

AdventureWorks作为第二业务域，只根据实际导出的schema构建产品等对象描述，不预写未经核验的字段名。官方镜像说明中的light版本限制需要登记；这一步还不声称满足④的数十张表验收。[D3]

OHR-Bench仅用于文档中的术语和实体提及，实体身份由文档元数据、原文定义或已审核映射支持；文档里同名公司不自动映射成业务库客户。其答案和证据标注进入评测空间，不进入在线候选索引。[D1]

**产出：**有来源、命名空间、有效版本和访问范围的概念与实体目录。

### 4.2 建立实体—别名—来源三层结构

| 记录 | 核心字段 | 必须满足的约束 |
| --- | --- | --- |
| `semantic_concept` | `concept_id, type_id, canonical_name, description, domain_id` | 类型可扩展，描述版本化 |
| `entity_record` | `entity_id, source_id, table_id, primary_key, display_name` | 同名不同ID可以并存 |
| `entity_alias` | `alias_text, normalized_key, entity_id, language, evidence_id, status` | 一个别名可对应多个实体；未审核别名不能成为强制映射 |
| `mention` | `mention_id, original_text, start, end, proposed_type, extractor_version` | 位置必须对应原始输入，使用半开区间 |
| `link_candidate` | `mention_id, target_id, retrieval_channels, rank_features, evidence_ids` | 所有候选可回溯；原始分数不是概率 |
| `rewrite_patch` | `start, end, replacement, target_id, reason, original_hash` | 应用前校验输入哈希，冲突区间不能同时覆盖 |

`type_id`和`concept_id`属于业务目录，`entity_id`属于真实对象，`column_id`属于数据库字段。三者不能用同一字符串混代。

### 4.3 复用②的抽取结果，保留开放类型出口

输入是原问题、当前业务范围及②输出的提及列表。先检查原文位置和类型；日期、数值、编号使用确定性规则再核验。

已知目录没有涵盖的类型进入`proposed_type`，由主模型给出描述与原文依据。它可以参与候选检索，但不能未经审核永久写入领域目录。低置信或未发现片段并不等于原文不存在实体，必要时用DeepSeek受限补充，再合并去重。

同一短语可能包含嵌套提及，例如专辑名中含年份；记录重叠关系，不能把年份从作品标题中拆出并直接变成查询时间。

### 4.4 三路召回，先覆盖再精排

建议同时查询：已审核别名精确匹配、字符／编辑距离近似匹配、上下文语义匹配。别名完全命中也要检查业务域与上下文。

候选数量不是固定真理，先在开发集上比较不同k值；记录三路召回覆盖率、噪声比例和延迟。只从已允许的来源返回候选，避免先全库检索再在答案阶段“隐藏”越权对象。

近似匹配不直接执行纠错。例如两个产品编号仅差一位，可能是两个真实产品，系统必须保留候选而不是默认修正。

**输出：**按mention组织的有限候选集，并保留“以上均非／未知”状态。

### 4.5 上下文重排与受约束选择

提供给DeepSeek的内容包括原句、提及边界、候选ID、简短描述、对象类型和必要关系，不提供全表数据。要求只能返回给定候选ID、`ambiguous`或`unresolved`，并指出支持证据。

程序检查候选是否存在、是否属于当前来源、描述是否适用于当前问题。选择分数可以综合别名证据、类型兼容、上下文匹配与关系一致性，但各路分数要先校准或采用秩融合，不能把不可比分值直接求平均。

可自动确认的典型情况是审核别名唯一命中且上下文不矛盾；多候选均合理时交③；全部候选不合适时返回未知，不强选最高分。

### 4.6 改写采用补丁，不采用自由扩写

在原文上生成最小替换补丁，标准对象ID是下游的主依据，标准中文句子主要用于展示。

| 可以自动做的操作 | 不应自动做的操作 |
| --- | --- |
| 用已确认标准名替换别名 | 把“最好”改成“金额最高” |
| 根据可靠匹配纠正对象拼写 | 把不存在的时间补成今年 |
| 展开已登记缩写 | 把金额改称利润或净额 |
| 保留原意地整理语序 | 改变否定、范围、比较方向或统计口径 |

对补丁建立前后语义约束：受保护数值、否定、时间、筛选、排序与分组不得未经确认新增或消失。冲突补丁先合并或退回，避免多次替换导致字符位置错位。

### 4.7 与③的往返只传确认结果

③接收`issue_id + mention_id + candidate_ids + reason`，面向用户显示业务选项。用户确认后返回选中的ID及意图版本，①不再让模型重新判断同一个点击。

新增别名可以记录为本会话有效证据，但不自动推广到全局。只有审核通过后才进入长期目录，防止一次错误选择污染其他用户。

### 4.8 与④⑤、文档侧的衔接

④接收原文、标准对象、类型和已确认条件，再做表字段定位。⑤只使用绑定后的条件构造参数，不把标准化文本直接拼接进SQL。

文档侧用相同`concept_id`建立术语检索别名，但必须标明来自哪个文档版本。不同来源的同名实体，在无真实关联证据时维持不同命名空间。

缓存键至少包含输入哈希、领域版本、候选目录版本和权限范围。目录变化后，历史答案中的对象仍能按旧版本解释，但不能不经校验用于新查询。

### 4.9 一次完整处理示例

设计用例：在固定Chinook快照核验存在`AC/DC`之后，用户问“acdc的专辑有哪些？”将`acdc`标成项目人工审核的别名，而不是声称数据集原生带有该别名。

| 步骤 | 处理 |
| --- | --- |
| ② | 标记“acdc”为艺术家候选提及，保留原文位置 |
| ①召回 | 从审核别名和对象描述找到`AC/DC`对应的真实艺术家ID |
| ①重排 | 上下文“专辑”支持艺术家解释；无合理竞争候选才确认 |
| ①改写 | 展示“AC/DC的专辑有哪些？”，同时输出对象ID |
| ③ | 检查需求已经明确，不为此强行询问年份 |
| ④⑤ | 用实际艺术家ID查相应专辑，附SQL与来源 |

对照例：“最火的acdc作品”。实体可以标准化，但“最火”仍可能是销量、金额或其他含义，必须交③，不能把一次实体修正扩展成业务口径猜测。

### 4.10 实现顺序与故障处理

先完成目录与gold标注，再做精确／近似召回，随后接语义召回和DeepSeek重排，最后加补丁校验、③回传和版本失效。每阶段都有可单独运行的验收接口，而不是先做九个界面按钮。

`NO_CANDIDATE`、`AMBIGUOUS`、`UNSUPPORTED_TYPE`、`INVALID_SPAN`、`STALE_CATALOG`和`MODEL_OUTPUT_ERROR`分开记录。技术错误有限重试；业务不确定进入③；没有依据则停止自动改写但保留用户原问题。

## 5 测试与评估

### 5.1 测试数据与标注

建议先做300条人工复核的问题及其变体，覆盖标准名、审核别名、未见别名、错别字、同名对象、未知对象、中英混写和嵌套标题。这个数量是项目起点，不是官方阈值。

每条记录原文、提及位置、对象ID、允许的改写、禁止变化的条件和是否应交③。同一原始对象的别名变体需要按实验目标分组；“未见实体”测试中，其所有变体都不进入训练。

分别报告实体未见、别名未见、类型未见和业务域未见，不能用一种较容易设置代替全部泛化。

### 5.2 指标定义

| 指标 | 计算或解释 |
| --- | --- |
| 原文片段F1 | 边界与类型分别报告，避免类型错掩盖边界能力 |
| 候选Recall@k | gold对象是否进入候选集合 |
| 标准ID准确率 | 选择的对象是否正确，未知对象单独统计 |
| 错误强链接率 | 应未知或多义时被错误绑定的比例 |
| 语义保持率 | 改写后受保护条件是否保持，结合人工审核 |
| 误改率 | 原本正确内容被改错的比例 |
| 端到端成功率 | 经③④⑤或RAG后，结果是否满足原始需求 |
| 成本 | 每题模型调用、Token、p50／p95耗时、目录检索开销 |

### 5.3 对照与消融

对照组为字典、字典＋模糊匹配、DeepSeek自由改写、完整方案。固定主模型和测试集，记录各组资源预算。

消融分别移除语义召回、上下文重排、未知对象出口和补丁保护。重点观察“看起来更流畅”是否伴随误改率上升，而不是只比较字符串相似度。

### 5.4 联调与性能

对①—③确认往返、①—④实体绑定、用户切换来源与修改指标开展多轮测试。加入旧目录结果延迟返回、两个会话同时请求和别名被撤销的场景。

目录规模按真实对象数量分层；压力测试扩容副本必须标为派生数据，不能据此宣称真实领域更多。近似索引的平均耗时由实测决定，不承诺固定对数复杂度；短文本片段候选上限、检索k值和模型上下文预算都记录在实验配置中。

### 5.5 竞赛展示与完成判据

展示原文高亮、候选解释、标准对象ID、修改差异和最终依据。成功例与拒绝误改例各至少一类。

完成意味着开放类型入口、未见别名、未知对象、③确认和下游查询都得到验证，不是仅展示“帝都→北京”这一条字典替换。创新可以定位为“有来源的最小改写与误改控制”，以对照实验说明收益；不宣称套用现成模型就是原创算法。

[S1] [用户整理的03技术方案样本](参考资料/03-用户样本.md)。沿用其“方案概述—设计原则—技术栈—实现方案—测试与评估—参考资料”的组织方式、主模型及共享接口思路；原文件保持不变。

[D1] [OHR-Bench：官方项目、数据结构与使用说明](https://github.com/opendatalab/OHR-Bench)。官方项目；运行材料与答案标注分离；来源与使用限制以项目说明为准。

[D2] [Chinook：官方PostgreSQL schema与样例数据](https://raw.githubusercontent.com/lerocha/chinook-database/master/ChinookDatabase/DataSources/Chinook_PostgreSql.sql)。官方脚本；引用字段须与实际固定版本复核。

[D3] [AdventureWorks镜像：版本及PostgreSQL适配说明](https://raw.githubusercontent.com/chriseaton/docker-adventureworks/master/README.md)。镜像维护者仓库说明；postgres标签被描述为light适配，不能预先假定完整OLTP结构。

[R1] [GLiNER: Generalist Model for Named Entity Recognition using Bidirectional Transformer](https://arxiv.org/abs/2311.08526)。2023预印本、2024研究；自然语言类型条件下的实体识别。

[R2] [GLiNER2: An Efficient Multi-Task Information Extraction System with Schema-Driven Interface](https://arxiv.org/html/2507.18546v1)。2025论文；重点阅读System design、Experiments及Artifacts。

[R3] [GLiNER2官方实现：模型、语言、字符边界及schema接口](https://github.com/fastino-ai/GLiNER2)。官方实现；不同checkpoint的能力不可混用；固定版本后核验中文。

[R4] [Scalable Zero-shot Entity Linking with Dense Entity Retrieval（BLINK）](https://arxiv.org/abs/1911.03814)。EMNLP 2020；候选召回与上下文重排分离。

[R7] [BGE M3-Embedding: Multi-Lingual, Multi-Functionality, Multi-Granularity Text Embeddings Through Self-Knowledge Distillation](https://arxiv.org/html/2402.03216v2)。2024论文；多语言及多种检索表示。

[R36] [LangGraph官方：Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)。中断恢复及幂等约束；用于03样本约定的持久状态。

[R37] [pgvector官方文档](https://github.com/pgvector/pgvector)。PostgreSQL向量索引；小语料保留精确搜索基线。

**使用说明：**论文中的数据集、模型训练与成绩仅用于理解方法，不移植为本项目实测结果。预训练组件可以使用，但本项目新增训练和正式验收数据遵守指定数据来源。引用外部组件时以固定版本、checkpoint、配置与软硬件实测为准。
