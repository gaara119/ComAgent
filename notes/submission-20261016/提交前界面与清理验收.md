## 测试命令与边界

后端实际执行：

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q -p no_model_plugin --basetemp=.runtime/pytest-submission-20261016 -p no:cacheprovider
```

该命令通过 `PYTHONPATH` 加载本机 `.runtime/submission-20261016/guards/no_model_plugin.py` 传输层保护；MockTransport 允许，实际外部 HTTP 请求阻断。原始命令、退出码0及耗时见上述记录；pytest 输出为784 passed。保护插件及本机辅助脚本不作为业务运行依赖。

前端实际执行（在 `frontend-workbench/`）：

```text
node scripts/build.mjs
node --test tests/contract.test.mjs
python -m unittest discover -s tests -p test_proxy.py -v
node tests/browser-check.cjs
```

浏览器运行连接独立受控接口，页面明确标注“接口模拟验证”，不将其作为真实模型正确率。浏览器环境与原始输出见前端验证目录。刷新检查使用 DOM click 事件；早期鼠标/键盘自动化等待超时单独保留，未把这两种手势标为稳定通过。

真实项目只另行进行了服务健康、双库就绪、静态页面与重复启动检查，没有向新界面提交业务问题。Windows 本机验证通过；POSIX 启动脚本和另一台电脑重新部署未实测。

## 首轮失败及实际调用记录

首轮旧路由测试仍假设 auto 单源回落不受支持，而且未显式注入模拟模型；此前尝试的网络保护没有生效，意外产生2次真实 DeepSeek 调用，共10892输入 token、190输出 token。已保留[调用汇总](initial-unintended-model-calls.json)、`initial-real-provider/` 原请求响应和[首轮失败输出](initial-backend-regression-output.txt)，不计入业务评测。随后只修正过时测试，使用模拟依赖与传输层保护完成784项回归，最终捕获中真实模型响应为0，见[隔离检查](final-model-isolation-check.json)。不得将整个整理任务写成0次真实调用。
