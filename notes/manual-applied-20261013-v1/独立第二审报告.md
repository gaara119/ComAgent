## 六个重要边界

1. **两个摇滚候选关系不等于合并查询授权。** `sp01-09/27` 首轮必须等待候选选择，不强制唯一绑定，也不默认并集。
2. **年份客户统计含义不自行补齐。** `sp03-10` 保留 2024 年和 Brazil 客户所在地，但不把它直接解释为当年购买客户；只读执行条件分支是验证候选标准，不是替用户确认条件。
3. **完整乐队名与裸词别名分开。** `sp03-28` 明确选择 Metallica 后才使用艺术家分支，没有初轮国家条件；之后显式换 Metal 流派和德国账单国的续问保留。两条证据不足别名继续停用。
4. **缺省全部数据不偷带隐藏年份。** `sp03-29/30` 初轮 Intent 与 SQL 用全部已有数据；明确改 2024 年之后才改变期间，后续对象/指标变更继续保持已确认期间。
5. **去重、修题和重新计分各自留版本。** 归档 `sp01-13` 不删历史失败；同首句而不同续问的 `sp03-08/23` 不删；旧 gold 和旧回答不冒充新题预测；不追溯重写旧 EX。
6. **人工和保留集边界保持。** 正式账本依据用户已提交的双方审核及明确应用请求；原条件通过、拒绝、证据不足等选择不改通过；无人工签名/日期代填；只读审查没有打开保留题正文或调用其预测，未提前计算保留集成绩。

## 两条新 gold

`sql-38` 题面为“找出文件大小已记录的曲目中，字节数最大的前3首，返回曲目编号、名称和字节数；按字节数降序，并列按曲目编号升序。”标准 SQL 具有 `WHERE bytes IS NOT NULL`、`ORDER BY bytes DESC, track_id ASC LIMIT 3`。未知大小排除；已知不足三条不补未知。只读执行的真实列类型为 `int4 / varchar / int4`，结果编号依次为 **3224、2820、3236**，大小为 **1059546140、1054423946、587051735 字节**。

`robust-23` 题面为“库里所有曲目的平均长度是多少毫秒？”标准 SQL 为 `SELECT AVG(milliseconds) AS average_milliseconds FROM public.track;`。全部非 NULL 曲目逐条等权，不过滤视频、不按购买量加权，单位毫秒。真实返回类型为 PostgreSQL `numeric`，标准值为 **393599.212103910933**。AVG 忽略 NULL，没有非 NULL 输入时返回 NULL。原提交条件在结构字段中明确保存。

本报告确认新 gold 与版本化材料一致。新题面下的实际问答预测、EX、模块回归和最终交付包核验由主任务另行运行并保存；截至本次第二审，没有把它们写成已实测。
