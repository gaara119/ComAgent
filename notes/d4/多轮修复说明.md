## 当前运行方式

1. 会话先从内存/磁盘读取已保存的结构化合同。
2. 明确修改、添加、删除或“某年呢”识别为当前问题续问；完整新问题仍新建意图。
3. 模型提出顶层 `set / add / remove`，程序核验本轮原文与真实值链接。无文字依据的指标、任务、排序、分组或期间改动被过滤；过滤值和元数据恢复为真实索引/此前状态记录。
4. 全列表 `set` 按本轮实际修改的字段合并，保留其它旧字段；明确删除使用 `remove`，不把归属迁移当作取消国家。
5. 版本递增，受影响的语义依赖进入 `invalidated`。当前 SQL 链路没有旧 SQL/结果缓存，每次确认或修改都会重新生成、校验并只读执行 SQL；公开元数据 `invalidated_execution` 明确列出重算的 SQL 计划、SQL 和结果。
6. 新响应公开 `metadata.clarify.semantic_contract`、`patch_history` 和 `intent_version`，用于逐轮核对；它们不需要更改共同 `schemas.py`。

本轮还修复了静态检查确定的“取消同比被正向同比覆盖”边界：明确命令句取消/不看比较时移除比较与旧基期，保留当前期间、国家和指标，并重新执行；“不是同比，只是解释术语”不会误触发取消或创建比较。仅补一个必要模块反例，没有扩造新模型题组；`multiturn-module-005`实际131项通过。

指标“发票张数”用 `invoice_count=COUNT(invoice.invoice_id)`，金额与计数明确区分。它是用户原文指定的指标，不是新增业务默认。
