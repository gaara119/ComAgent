# D2 A：值索引、五级链接、改写及 SQL 绑定核验

本文件记录新增模块及使用方法；D2 九项验收、开发集 EX 和人工审核状态以主验收报告为准。没有修改共享 `schemas.py`，没有修改 D1 题库或验收报告，没有导入或重建数据库。

## 实际接入的运行路径

`/api/chat` → 原 `pipeline.chat` → 真实目录 → 值索引及五级级联 → 受控补丁改写 → 原 SQL 生成器 → 原只读 AST 校验 → 绑定硬核验 → psycopg 参数化只读执行 → 原统一结果协议。

所有阶段仍使用原 `TraceRecorder`。`value_link` 汇总实际总耗时；`value_link_exact / pinyin / fuzzy / vector / llm` 在真实计算及调用前开始计时，未执行的向量步骤明确为 `skipped`。页面可从 `metadata.nlu` 展示原问题、改写文本、字符补丁、标准值绑定、候选及来源标识。

## 源码与接口

| 文件 | 作用 |
|---|---|
| `scripts/build_value_index.py` | 从目录列举所有文本列，使用现有只读账户扫描 DISTINCT，起草待审别名，构建拼音及 BGE 值索引 |
| `scripts/review_aliases.py` | 在当前内容 SHA256 和明确别名 ID 上记录实际人工决定；不会自行审核 |
| `qa_agent/nlu/value_index.py` | 不可变记录、规范化、拼音、哈希及向量形状校验、运行时索引缓存 |
| `qa_agent/nlu/linker.py` | 精确、拼音、RapidFuzz、向量 Top-5、合法候选模型裁决及最小歧义拦截 |
| `qa_agent/nlu/rewrite.py` | 验证字符范围、原文及依据，拒绝重叠，从后向前应用补丁 |
| `qa_agent/sql/generator.py` | 继续接收真实目录；增加可选 `intent` 与 `bindings`，保留旧调用方式 |
| `qa_agent/sql/validator.py` | 保留原只读校验；新增 `validate_value_bindings` 与字符串 AST 参数化 |
| `qa_agent/sql/executor.py` | 增加可选 `parameters`，继续使用原只读事务、5 秒超时、结果上限 |
| `qa_agent/pipeline.py` | 将以上步骤接入原 SQL 实际执行入口，校验失败可有限技术修复 |

链接器内部结构与公共协议分开。已核验的条件放入原 `intent.filters`，未确定候选放入原 `intent.unresolved`；出现真实歧义时返回已有 `NEEDS_CLARIFICATION`，提供明确候选并要求重新提问。此处不实现 D3 的多轮恢复状态机。

## 值索引和别名审核边界

构建器仅从可信目录选择 SQL 标识符，使用 psycopg 标识符引用；每个文本列读取最多 5000 个非 NULL 不同值。读到 5000 时记录“至少 5000，未完整索引”，不声称已覆盖。构建审计逐列记录成功、跳过、失败和耗时。

本次实际扫描为 **34 个文本列、5528 个字段/标准值记录、5184 个不同表面文本**，列扫描无失败。实际生成的向量矩阵为 **5528 × 1024**，复用 D1 BGE-M3 CPU/int8 适配器；相同表面文本只编码一次，再按字段记录扩展为明确的一行一记录。姓名和邮箱等全量索引数据不写入公开构建日志。

实际模型起草了第一批 74 行别名以及 Italy 的 6 行补充，主执行人另外保留总计划指定的歧义映射草案，当前共 81 行。用户明确要求所有人工审核先跳过，因此**生产运行索引中已审核别名为 0**，全部待审别名均未启用。真实中文说法如需模型语义判断，只使用数据库真实标准值候选，不向运行模型提供待审别名表。

审核记录必须具备 `review_status=approved` 和非空 `reviewer`；`pending`、`rejected`、无审核人、不存在的标准字段/值均不进入运行索引。审核通过后需要重新构建值索引；此项由最后的统一审核表安排，不在本次开发过程中冒充完成。

```powershell
.\.venv\Scripts\python.exe scripts/build_value_index.py --catalog data/catalog/chinook.yaml --output-dir data/indexes/values --aliases data/aliases/aliases.csv --audit-output eval/reports/d2-acceptance/value-index-build.json
```

该命令仅查询数据库并构建派生索引，不初始化或导入数据库。`--draft-aliases` 在另一个 CSV 路径上使用实际配置模型起草，所有行初始均为 `pending`；不会覆盖已存在的别名表。`--no-embeddings` 只用于准备/审计，不能代替 D2 向量验收。

## 决策和语义保护

五级匹配的分数不是正确概率：精确和拼音表示形式一致，字符分数为 RapidFuzz `ratio / 100`，向量分数为同一模型的归一化余弦值。默认字符阈值为 0.82、领先第二名至少 0.08；向量阈值为 0.82、领先第二名至少 0.08。阈值都可由配置调整，只使用开发测试。

最初任意设置的字符阈值 0.86 无法匹配方案中的 `Brasil → Brazil`：实际字符分数为 0.833333。模块测试暴露了这一错误，调整到 0.82 并保留领先差距后通过回归。详见 `eval/reports/d2-acceptance/a-error-records.json`；没有使用保留集或伪造人工批准。

同名在客户国家和发票账单国家重复出现时，查询对象先约束字段，不随便选第一列；`来自巴西` 的真实筛选优先于“名字、姓氏、城市”等输出列用语。`LIKE` 开头/结尾/包含问题保留原意，不误加完整值等号条件。明确的否定保持 `!=`，明确的 `或`/列表选择保持 `IN`。

合法但没有记录的值保持原问题，不能用近似国家替换。对 `Antarctica / Wakanda / Atlantis` 等已明确的无匹配值以及通用“保留原值、恰好为、不纠错、不做近似”指令，禁止近似链接；返回 0、NULL 或空记录仍沿用原数据库执行和回答语义。

模型裁决只能使用提供的候选 ID。向量 Top-5 不抹掉字符 Top-5：最终允许池保留两种真实召回的候选及各自 `stage_scores`，最多 10 个不同对象，不混用不同方法的原始分数。动态 JSON Schema 将候选 ID 与片段 ID 限制为真实候选枚举，非法输出使用原 `JsonLLM` 可见的格式校验及有限重试。未知 ID、重复片段、遗漏片段、未确定却给出已选对象均属于技术错误；模型超时不伪装成用户歧义。技术错误仍保留已经产生的候选、来源和步骤，索引已加载时不会误报为未加载。

总计划已明确“摇滚”对应 Rock / Rock And Roll 的真实歧义，因此新增的是**禁止执行的歧义保护**：必须在实际值索引中同时找到这两个标准候选，随后仅返回候选供重新提问，不绑定、不改写、不执行 SQL。该规则的来源是总计划 §3.6.4，不是启用待审别名或选择新的默认流派。

## SQL 硬核验和安全

生成器收到的绑定不是一句提示：生成后使用 SQLGlot 资格解析核对真实物理表、字段、操作符和字符串值。条件必须是 `WHERE / HAVING` 中必需的约束。标准值只出现在输出列、注释、其他表或另一个无关联子查询中都不能代替绑定；`OR 1=1`、增加另一国家的 `IN` 集合、某个 UNION 分支漏掉条件均被拒绝。重复读取同一目标表的作用域必须分别保留对应绑定。

端到端界面还发现了一个目录错误：用户明确要求仅查询不存在的 `d2_nonexistent_table_20261010`，模型却生成 `SELECT 1 FROM customer LIMIT 0`，原链路误报空结果。现在对“明确 ASCII 表名＋表”“表名为”“table named”等来源先做目录检查，未知来源直接真实失败，不调用模型或执行器；明确的已知来源也不能被生成器换成另一个表。模型明确说明无法执行或生成未请求的零行常量占位 SQL 时，拒绝把占位结果冒充数据库回答。合法无匹配筛选、COUNT=0、用户指定前 0 行，以及单独调用原只读执行器的合法 `SELECT 1` 均保留。

核验允许表别名以及一致的 `LOWER / UPPER` 写法，不采用全局字符串替换。D2 对复杂派生表的外层条件传播保守拒绝；这些不在当前单表基本题所需范围。原所有写操作、数据修改 CTE、SELECT INTO、锁定、多语句、目录越权、函数白名单和单表限制仍在。

有有效绑定时，执行前通过 AST 将字符串常量转换成 psycopg 独立参数，API 展示的 SQL 仍为已经核验的原始可读 SQL。运行日志只记录参数化 SQL，不序列化密码、连接串或参数字典。无绑定时保留旧执行方式。

## 实际验证与局限

最新 A 新增模块验证 **63 项通过，3.27 秒**，原始输出在 `eval/reports/d2-acceptance/a-nlu-final-tests.txt`。此前新增 61 项与原 D1 API/AST/trace/LLM 69 项合并，**130 项通过，6.39 秒**，原始输出在 `eval/reports/d2-acceptance/a-module-tests.txt`。

上述模块测试明确使用模拟模型/向量/人工审核记录夹具，验证逻辑而非宣称真实 NL2SQL 成绩。包括五级链接、候选限制、同音冲突、待审别名隔离、重复补丁、安全条件及语义保护。其中另有实际只读 PostgreSQL 连线测试：模型固定返回 Brazil SQL，参数化后查询真实数据库得到 **5 位客户**，这验证执行连线，不算真实模型 EX。

随后根据实际运行发现的缺陷完成修复：职位拼写变体的字段抽取、字符候选被向量候选覆盖、非法模型候选 ID、摇滚真实歧义、工程检查用语的误抽取。修复后新增与原 D1 合并验证 **138 项通过，4.52 秒**，真实输出在 `eval/artifacts/d2/a-live/module-after-live-fixes-final-v2.txt`。未删除首轮失败记录，见 `eval/artifacts/d2/a-live/live-error-fixes.json`。

真实 API/model/read-only DB 工程测试最终 **11/11 通过**：清晰库题、标准值、英文拼写、标准值的分隔拼音、中文语义、未批准别名诊断、Narnia 无匹配、摇滚双候选、职位拼写、`ba xi`、`jia na da`。待审中文名称没有作为精确/拼音别名启用；`ba xi / jia na da` 此次由真实合法候选模型裁决绑定 Brazil / Canada，不能把它记成已批准别名的拼音命中。完整原始响应在 `eval/artifacts/d2/a-live/final/api-responses.jsonl`。
