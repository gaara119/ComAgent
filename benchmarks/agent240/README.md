# 原240题七维评测使用说明

这套工具对原40题和原200题的历史真实预测重新计分，保留题目、Gold、实际配置、审核与成本证据。它不发送问答请求，不访问数据库，不调用模型裁判，也不生成新测试数据。

[项目运行说明](../../README.md) · [七维结果报告](results/240-seven-dimensions-v1/report.md) · [机器可读汇总](results/240-seven-dimensions-v1/summary.json)

## 1 数据与版本

| 批次 | 原题数 | 历史配置 | 预测数 | 任务构成 |
|---|---:|---|---:|---|
| `final200` | 200 | BASE / FULL | 400 | SQL170、跨源20、RAG5、会话正文5 |
| `legacy40` | 40 | BASE / C1 | 80 | SQL34、跨源4、RAG1、会话正文1 |

合计240个协议条目、480条历史预测：204道SQL、24道跨源、6道RAG、6道会话正文。两批有35道相同题面，连续对话中的后续问题也相互依赖；这不是240个独立样本或240道RAG检索题。批次命名空间防止同名题号混淆。

`FULL`与`C1`采用各批实际功能开关，不能统称为同一个增强版本。历史源码与协议差异在[manifest](data/manifest.json)中保留，不能将重计分结果当作当前同一源码的因果消融。后补32道合成题及专属资源已经删除，不参与该入口。

## 2 环境与执行

需要Python 3.12与项目运行依赖。已按根README建立`.venv`时直接复用。无需Docker、PostgreSQL服务、GPU、本地向量权重或API密钥。

在包含根README的项目目录执行：

```powershell
.\.venv\Scripts\python.exe -m benchmarks.agent240.evaluate --bundle benchmarks/agent240/data --output .runtime/agent240/my-run
```

1. 读取`data/manifest.json`，检查题库和历史预测文件哈希。
2. 校验240个唯一批次题号，保留40/200分母和缺失项。
3. 用原参考比较SQL结果，用真实响应哈希绑定已有AI业务审核；未核验项不转成通过。
4. 汇总准确性、效率、异常、引用与过程结构等七维检查，保存新报告。

输出目录已存在会拒绝执行；再次运行换用例如`.runtime/agent240/my-run-2`，不要删除旧结果来覆盖。当前命令只重算已保存预测，新增模型调用与SQL执行均为0。当前Docker未就绪，尚未完成当前源码的新一轮在线240题回放。

## 4 七维指标与边界

| 维度 | 计算对象 | 当前可报告内容与限制 |
|---|---|---|
| 结果 | 业务Accuracy、SQL结果EM/行F1、文本EM/F1、外部任务成功 | SQL适用分母为190和38；完整文本Gold仅10和2题。未知不隐藏，词面匹配不替代业务语义 |
| RAG召回 | 最终返回证据与原参考文档/引句 | 文档返回覆盖40/68；缺完备Top-K/qrels，Recall@K、MRR、nDCG未核验 |
| 证据正确性 | 引用ID、原句覆盖、位置字段结构 | ID34/34、参考引句53/88、位置结构31/34；不等于引用语义支持或原PDF定位正确 |
| Agent过程 | trace、实际工具、计划DAG与依赖 | trace480/480、DAG48/48、所需工具类型出现383/406；不替代路由和条件保留的语义判断 |
| 稳定异常 | 任一尝试错误、最终FAILED、澄清与真实恢复尝试 | Error Rate分开列示；没有失败后的真实恢复尝试就不形成恢复率分母，澄清不算故障 |
| 成本效率 | HTTP耗时、物理provider调用、输入/输出和缓存token | 755次历史物理调用、7,592,425输入、168,251输出；含失败重试和正文登记，新运行调用0次 |
| 安全 | 只读SQL AST、执行前校验、允许工具类型 | 413/413可检查SQL满足AST及前置校验，另有66项离线安全与权限回归；不是攻击防御率或实际PG权限测试 |

SQL结果EM使用完整列数、全表一致列映射和重复行；按参考要求检查排序，不做数值舍入、尺度转换、删列或NULL填充。行F1比较完整行多重集，忽略行序，保留重复行。未观察预测或无效参考保持未知；已观察但没有交付成功表计为结果不匹配，与业务语义未知分开。

文本EM采用规范化后的完整文本相等，文本F1以中文单字、其他语言词项和符号的多重集计算。原Gold中的局部SQL/跨源文字答案不能冒充整题文本Gold。Error Rate不等于`1−Accuracy`，合法工具和合法引用ID也不等于答对。

## 5 已有结果怎么解释

| 历史比较 | 业务正确 | SQL结果EM | 外部任务交付 |
|---|---|---|---|
| 原40 BASE→C1 | 25/40→26/40，62.50%→65.00% | 20/38→21/38，52.63%→55.26% | 19/40→20/40，47.50%→50.00% |
| 原200 BASE→FULL | 133→123正确，两组各4项未知 | 90/190→86/190，47.37%→45.26% | 72→88已确认成功，FULL另1项未知 |

原40有改善，原200在业务与SQL结果上有退步，同时外部任务交付增加；必须结合各配置实际源码与开销解释。不能只选择上升指标宣称整体提升。不同批次时延不合并成当前性能，真实费率未核验，不能用token变化直接当作费用变化。

## 6 本地检查与CI

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_agent240_metrics.py tests/test_sql_validator.py tests/test_source_scope_and_tool_permissions.py
```

指标检查覆盖缺失参考、缺失usage、响应审核绑定、数值/NULL、重复行与分母。SQL及来源权限检查使用离线夹具，验证DML/多语句/危险函数拒绝、目录约束、禁止工具调用前拦截和续问权限恢复，不连接数据库或模型服务。

[评测CI](../../.github/workflows/rag-eval.yml)执行无API回归并使用本证据包重算240题。云端状态以Actions为准；单元测试通过不等于开放答案质量达标、故障恢复已测或攻击防御成功。
