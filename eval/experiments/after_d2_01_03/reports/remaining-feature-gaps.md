# 专项剩余功能问题和人工核对重点

此清单来自真实输出和逐条 AI 阅读。它没有自动修复、改标签或启用别名。最终源码保留 V1，V2 的新增守卫已撤回；AI 预审和冻结自动分数分开保存。具体原编号、题面、参考、全部交互和 provider 原文在同目录 `manual-review/①③专项统一待人工审核表.html` 中。

## ① 值链接与改写

- 中文错字或拼写错误并不都进入 resolved binding。部分正确结果没有 binding／改写证据，不能据结果相同称完整识别链通过。`sp01-04`、`17` 的 France 条件能执行，但对应绑定与改写缺失。
- `sp01-05`、`18` 的技术修复可能把 artist.name 问题改成 album.title，0 行不证明原查询正确。跨表媒体／流派问题仍被当前 source gate 拒绝，不能把正确候选字段或生成 SQL 当作已完成回答。
- 对应多个合法候选时应保留候选关系。`sp01-27` 真实保留 Rock / Rock And Roll，并没有唯一绑定；冻结评分器比较 IN 列表和多个等值候选的表示不兼容，原 overcorrection 指标不能当成已证明过纠正。
- `sp01-30` 原题显式半开期间与 gold 上界不同；相同的未来 0 计数不能证明时间逻辑正确。参考争议另存，原评分不重写。

## ③ 澄清和后续修改

- 最终 V1 的 `sp03-14` 把“每年”误判为国家候选歧义，属于实际多余澄清；`sp03-22` 漏提取原题已明确的分子，补分母后继续反问分子，没有执行 SQL。
- 语义提取与规则之间仍有时期覆盖不一致；`sp03-18` 某轮实际 SQL 覆盖两年但保存 intent 只剩一年，状态并不可靠。
- 合法的普通修改可能被识别为新问题，丢失已确认范围。`sp03-26` 的平均发票金额修改丢失同比和时期；`sp03-27` 修改分子没有保留原 2023 年及全库分母。V1 第一次 numerator patch 的改善不能代表这些后续问题已修复。
- 修改艺术家筛选为流派仍有 conflict，旧筛选替换规则的适用范围需要补齐。未问到的补充不能由控制器借隐藏 gold 自动填写。
- 规范 rank_object 和自由中文对象没有完全统一。`sp03-30` 保存“客户”而不是 canonical customer 后可能绕过原期间规则，直接全库 Top10；缺期间、TopN 和模型补丁字段需分别核对。它不等于收到参考中的隐藏年份。
- 分子／分母的地区归属需要独立表示，不能把国家一律写到全局 WHERE。撤回 V2 后，原有比例问题仍待修复；V2 中的百分比等价语法和多轮来源继承缺口作为后续工程证据保留。
- 初始分类、必要澄清召回、完整多轮完成不同。最终 V1 原固定 L2 完成是 **0/11**，不会用 **11/11** 初始必要澄清召回替代它。

## 参考和评测控制器

- 未审核的地区默认、期间要求、Top1/Top10、通用销售额／客户归属，以及原题明确条件，不能用当前程序行为倒推参考。
- 原 11 个 annotation pending 保持不变；新发现的参考争议另外列，原49题评分分母保持冻结。每条的最终人工结论将由用户决定。
- 控制器按实际 issue field 回答，不能遇到未知字段就猜 gold。已有 bundled metric/rank_object、未覆盖 key 和地区归属配套等限制会导致 controller_unanswered；这与业务系统返回错误分别记录。
- 冻结评分器要求精确结果列和 AST 合同；额外姓名列、同比基础金额列或数学等价 SQL 会进入失败／AI_pending。逐项 AI 语义意见不能默默替换原分数。
