## V1：保留有直接证据的局部补丁修正

只修改 `qa_agent/clarify/prompts/intent_patch.txt`，不同时改模型、索引、别名、规则、状态机或 SQL 生成 prompt。修正明确：按当前实际卡片询问的字段输出补丁；分子、分母的描述不变成全局地区筛选；使用现有规范字段；保留无关已确认条件。

真实案例 `sp03-27` 同一句补充“巴西居住客户的销售额。”在 V0 设置 `region_scope` 和全局 `filters`，没有填写正在被问的 numerator，触发 conflict。V1 只设置 numerator，保留 2023 年，版本 1→2，剩余问题只有 denominator。随后用户实际回答分母，主查询确实计算出比例 `0.04216533923932024362`，但之后修改分子时又走新问题路由，整题仍未完成。

具体原始 provider 对照见 [目标补丁观察](../runtime_eval/runs/V0-V1-sp03-27-target-patch-observation.md)，全文、差异和两遍审读依据见 [V1 改动记录](../runtime_eval/version-changes/V1/change-record.json)。这支持局部字段补写改善；总体固定分数未增加，不宣称显著提升或完整多轮修复。初始意图抽取 prompt 没有改变，其他初始输出的单次波动不能归因 P3。

## V2：实际执行两轮上限内的第二轮试验，发现新问题后撤回

直接原因来自 V0 `sp03-22`：第一条 SQL 的国家只在分子 CASE 内，分母为全期间金额；普通绑定守卫迫使修复 SQL 把 France 加到全局 WHERE，导致错误的 100%。V2 尝试对唯一、已确认 `customer.country` 分子和同期间全库发票金额分母作独立证明。改动前后准确字节、目录来源核对、模块反例与完整 60 条实跑均保留。

模块层面，V2 新守卫与旧账单守卫联合 **72 项通过**，全模块 **462 项通过**。但是实际端到端暴露了两个新增拒绝：

- `sp03-22`：最后 SQL 没有 France 全局 WHERE，采用合法的 `ROUND(条件SUM/SUM(total)*100,2)` 百分比表达。新守卫仅支持另一种等价乘法位置，三次拒绝合法 SQL。不能把拒绝理由当成 SQL 分母错误的事实。
- `sp03-27`：真实用户已经给出中文分子，并通过当时的值链接；补丁保存筛选后丢失别名证据元数据，下一轮只获得 canonical Brazil。新守卫没有取得先前已核验的中文 surface，错误地拒绝来源证明。最后 CASE 比例 SQL 没有全局国家筛选，但未执行成功。

具体证据见 [V2 目标观察](../runtime_eval/runs/V2-001-target-guard-observations.json) 和 [V2 完整试验报告](../runtime_eval/runs/V2-001-trial-report.md)。额外一次明确口径 DEV API 观察仍返回地区澄清，没有形成通过结果；独立只读查询实际金额为 France `36.66`、全部发票 `477.53`、比例 `0.07677004586099302662`。这一观察见 [补充 API 与只读核验](../regression/final/ratio-live-001/report.json)，没有混进 60 条 cohort 或原分数。

因此 V2 没有可靠端到端改善，并引入合法 SQL／多轮证据拒绝，按专项要求恢复本轮自己的增量。**实际恢复** `pipeline.py` 和 `sql/validator.py` 的 V1 精确字节，移除只属于本轮的 helper 和 active 测试文件；它们的全文保留在试验 archive。未使用 reset/clean，未改数据库，未覆盖其他工作。

实际恢复记录见 [恢复到 V1](../runtime_eval/version-changes/V2/actual-restore-to-V1.json)。恢复后完整模块实测 **415 项通过，14.76 秒**，新快照的所有 runtime 文件和 safe_config 与 V1 相同；API/UI 已重新装载最终 V1。见 [最终装载记录](../runtime_eval/V1-final-restart-record.json) 及 [最终模块命令](../regression/final/modules-final-V1-001/command.json)。最终 D2 回归另存，不沿用早先 D2 报告冒充当前结果。

## 评分与审核边界

全部合成案例保持人工 `pending_human_review`。最初 11 条标注争议独立于后续发现的新参考争议；所有 60 条都有实际输出，争议样本保留输出而不强行二分类。原 SQL AST 表示未证明、controller 不能合法回答的字段、补丁的残余条件丢失，都保留相应失败或待核验状态。

V0/V1/V2 共实际 244 个 POST、344 个 provider attempts，预测 token 共 `1,513,788`；生成与参考审查调用另计，额外诊断和 D2 回归也另计。未取得精确费用，不猜金额。每次调用最多 3 次尝试，澄清上限 3；未对无响应请求重发。所有保留集预测为 0。
