# 冻结版本完成后的失败分类

此脚本只读取已保存的score、API请求/响应、checkpoint和provider副本，不执行预测、不重跑SQL、不修改gold或scorer。root正式冻结应包含新增分类脚本。V0完成后执行，输出目录必须是新目录：

```powershell
.\.venv\Scripts\python.exe eval/experiments/after_d2_01_03/runtime_eval/classify_failures.py --cases eval/experiments/after_d2_01_03/data/cases-v6-reviewed.jsonl --scores eval/experiments/after_d2_01_03/runtime_eval/runs/V0-001-scores.json --run-dir eval/experiments/after_d2_01_03/runtime_eval/runs/V0-001 --output-dir eval/experiments/after_d2_01_03/runtime_eval/runs/V0-001-classification
```

产物包括`failure-classification.json`（全部60条的观测、分类证据与下一步核验）、`failure-classification.md`（可逐条点击对应请求、响应、trace和provider记录）、`semantic-review-pending.jsonl`（未证明SQL等价清单）以及`pending-label-review.jsonl`（冻结时待确认标签及原AI理由）。每个引用记录文件SHA；provider副本核对归档SHA及trace_id，不凭状态猜模型是否错误。

分类覆盖模型、链接/别名、规则目录、会话状态、SQL、尚未实现、标注/评分和环境。`observed_failure_boundary`仅说明真实错误发生的边界，`direct_observation`是直接记录，`hypothesis`仍须查证。错误SQL可能源于理解、状态或参考争议；不把`FAILED`、`NEEDS_CLARIFICATION`、`UNSUPPORTED`等状态自动当最终根因。所有`root_cause_confirmed`初值为false。

SQL等价审查必须读取原问题、实际逐key回答和普通修改；逐项确认标准column/operator/value、候选、metric/grain、JOIN及CASE分子分母、期间边界、排序/并列、LIMIT和NULL语义，并比较精确表值。结果相同不能证明条件正确。未证明SQL等价保持`AI_pending`；review_verdict、reviewer、review_time初值为空。本脚本只生成核验任务，不能替代实际审核，也不会将待确认题加入确定对错分母。

核验后如需调整标注或评估解释，应由root保存理由、新版协议/标签和独立重评分产物，对所有版本一致适用，原score/raw仍保留。若只是发现系统失败，先完成V0全轮及分类，再判断是否有一类适合prompt修复；最多两轮优化，不能按测试题ID硬编码答案。
